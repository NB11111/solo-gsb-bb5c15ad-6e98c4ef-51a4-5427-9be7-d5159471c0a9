# 舞台换景顺序优化

一个舞台演出换景顺序优化 Web 应用：录入不超过 **12 个场景**及其道具集合，设置**前后依赖**、**固定序位**、**禁止相邻**三类约束，系统自动计算满足全部约束且**道具增减次数最少**的演出顺序，并展示每次换景的道具增减明细。无解时会指出一组可复现的冲突约束。支持**标准编排**与**时长受限编排**两种模式；支持保存方案并随时重新载入编辑。

## 快速开始（单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**

> 依赖安装与数据目录初始化均随容器启动自动完成，无需额外步骤。
> 若使用旧版 Compose 插件，命令为 `docker-compose up --build`。

停止：`Ctrl+C` 或 `docker compose down`。保存的方案存放在名为 `plans-data` 的卷中，重启不丢失。

## 本地开发（不用 Docker）

```bash
npm install
npm start          # 访问 http://localhost:3000
npm test           # 运行求解器单元测试
```

要求 Node.js ≥ 18。方案数据默认保存在 `./data/plans.json`（可用环境变量 `DATA_DIR` 修改）。

## 功能说明

- **场景与道具**：最多 12 个场景，每个场景一组道具（逗号分隔录入），并可设置：
  - **时长**（非负数）：该场景占用的演出时间；
  - **必演**：时长受限模式下必须入选；
  - **可选价值**（非负数）：该场景作为可选场景入选时贡献的价值。
- **编排模式**：
  - **标准编排**：全部场景参演，只最小化道具增减次数；
  - **时长受限编排**：设置整场时长上限，求解时从场景中选择**包含全部必演项**的子集；
    **未入选场景不参与任何约束**，**固定序位按入选后的演出序列**（第 1、2、3… 位）计算。
    结果依次展示入选/舍弃场景、已用与剩余时长、入选可选价值总和与换景明细。
    - 第一目标：**最大化入选可选场景的价值总和**；
    - 第二目标：**最小化道具增减次数**；
    - 同分时按场景下标字典序取确定结果。
    - 若**必演场景总时长已超过上限**，返回 `required-overtime` 提示；
    - 若包含全部必演也**没有可行编排**（必演内部冲突、或上限内可选场景无法补位），
      返回 `no-feasible-arrangement` 并指出冲突约束。
- **约束**：
  - 前后依赖：场景 A 必须排在场景 B 之前（一方未入选时该约束忽略）；
  - 固定序位：某场景必须排在第 N 位（入选后序列中的序位）；
  - 禁止相邻：两个场景不得紧挨着演出。
- **优化目标**：`开场布置道具数 + 各次换景（撤下数 + 上台数）之和` 最小。
- **换景明细**：依次列出开场布置与每次换景撤下/上台的具体道具及次数。
- **无解分析**：优先报告依赖环；否则给出一组极小冲突约束核心（去掉其中任意一条即恢复有解）。
- **方案管理**：保存、列表、载入重新编辑、删除；模式、时长上限与场景新字段一并持久化，旧方案载入时按标准模式与零值字段兼容。

## 算法

场景数 n ≤ 12，采用子集动态规划（Held-Karp 风格）：状态为 `(已排场景集合, 末尾场景)`，
转移时校验前置依赖、固定序位与禁止相邻约束，代价为相邻场景道具集合的对称差大小。
复杂度 `O(2^n · n²)`（12 个场景约 70 万状态），求解在毫秒级完成，结果保证全局最优且确定（同代价取下标字典序）。

时长受限模式枚举所有"必演掩码的超集且总时长不超限"的候选子集，对每个子集运行同构的子集 DP
（未入选的前置依赖与固定序位按入选序列解释），再按 `(可选价值 ↓, 道具增减 ↓, 顺序字典序 ↑)` 选全局最优；
DP 数组在候选子集间以 generation 标记复用，总工作量约 `O(3^n · n)`，12 个场景数百毫秒内完成。

## API 简介

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/solve` | 求解，body 为 `{ scenes, constraints, options? }` |
| GET | `/api/plans` | 方案列表 |
| POST | `/api/plans` | 新建方案 |
| GET | `/api/plans/:id` | 读取方案 |
| PUT | `/api/plans/:id` | 更新方案 |
| DELETE | `/api/plans/:id` | 删除方案 |

请求/响应中的场景形如 `{ id, name, props: [], duration?: number, required?: boolean, value?: number }`；
约束形如 `{ dependencies: [{before, after}], fixedPositions: [{sceneId, position}], forbiddenAdjacencies: [{a, b}] }`；
`options` 形如 `{ mode: 'standard' }`（缺省）或 `{ mode: 'limited', timeLimit: number }`。

时长受限模式成功响应额外包含：`selectedScenes`、`discardedScenes: [{id, required, duration, value}]`、
`totalValue`、`usedDuration`、`remainingDuration`、`timeLimit`；
无解响应为 `{ ok:false, reason: 'required-overtime' | 'no-feasible-arrangement', message, ... }`。
